# Приватность и обработка данных

- **Community по умолчанию не хранит письма.** `storage.store_bodies: false` → в БД попадают id, канал,
  домен отправителя, скор, вердикт, список сигналов (без evidence). Тема и тело — нет.
- **Business:** `store_bodies: true` + `PL_ENC_KEY` (32 байта, `phishlens keygen`) → ParsedMail
  шифруется AES-256-GCM (internal/crypto) и хранится как `enc:<base64>`. Ключ вне БД.
- **Ретенция:** `storage.retention.submissions: 90d` — фоновая очистка раз в час (`serve`).
- **Удаление по запросу:** `DELETE /v1/submissions/{id}` (analyst/admin), фиксируется в audit.
- **Экспорт по запросу:** `GET /v1/privacy/export?subject=user@example.com` (admin, только
  в пределах организации) возвращает все записи субъекта и фиксируется в audit. Тела писем
  присутствуют только если они были явно включены и сохранены в зашифрованном Business-хранилище;
  Community экспортирует доступные метаданные без тела.
- **Внешние вызовы:** перед LLM — редакция PII (internal/llm/redact.go: email, телефон, ИИН/БИН,
  карты по Luhn, IBAN). В TI/DNSBL уходят только домены/IP/хеши, никогда текст.
- **Webhook/SIEM:** событие содержит вердикт, скор, домены, хеши вложений, id сигналов — без тела письма
  (тест TestWebhookSignature это проверяет).
- **Вложения** никогда не записываются на диск и не исполняются: только листинг архива и статические признаки в памяти.
- **Изображения** перед внешним OCR/vision вызовом декодируются и повторно кодируются в PNG, поэтому EXIF/GPS-метаданные не покидают процесс.

Экспорт и удаление данных субъекта реализованы отдельными API; оператор всё ещё должен
проверить юридические сроки ответа и процедуру подтверждения личности вне сервиса.
